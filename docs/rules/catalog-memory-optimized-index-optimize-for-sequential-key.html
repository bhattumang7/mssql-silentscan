Memory Optimized Index Optimize For Sequential Key

silentscan/catalog/memory-optimized-index-optimize-for-sequential-key

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

A memory-optimized table's index is declared WITH (OPTIMIZE_FOR_SEQUENTIAL_KEY = ON) - oracle-confirmed (Msg 10794: "The index option 'optimize_for_sequential_key' is not supported with indexes on memory optimized tables.") the statement never deploys, since this option only mitigates last-page-latch contention in the on-disk B-tree structure memory-optimized indexes don't use. Catalog-only structural fact.

How can I fix it?

Remove OPTIMIZE_FOR_SEQUENTIAL_KEY from the index - memory-optimized indexes have no last-page-latch contention to mitigate.
