Smalldatetime Rounding

silentscan/write-loss/smalldatetime-rounding

A medium-confidence or low-confidence finding of this same rule links here too - only the finding's certainty differs, not the underlying issue.

Why is this an issue?

An INSERT/UPDATE or SET variable assignment assigns a DATETIME or DATETIME2 value (or a string literal with a seconds component) to a SMALLDATETIME target - SMALLDATETIME stores whole minutes only, so the seconds and fractional seconds are silently rounded to the nearest minute (30 seconds or more rounds up), with no error.

SMALLDATETIME stores whole minutes only, with an accuracy of one minute. When a DATETIME or DATETIME2 value, or a string with a seconds component, is assigned into a SMALLDATETIME target, SQL Server does not raise an error. It rounds the value to the nearest minute: 30 seconds or more rounds up, less than 30 seconds rounds down. A value of 10:20:45.500 is stored as 10:21:00, and 10:20:29 is stored as 10:20:00.

The change is small enough to go unnoticed, but it is real. Two events a few seconds apart can collapse into the same stored value, an event can end up recorded a minute later than it happened, and a later comparison against the original value no longer matches. The same rounding applies to variable assignment and to INSERT or UPDATE into a table column.

How can I fix it?

Declare the target as DATETIME2 with the precision the data needs if the seconds matter. If whole minutes are genuinely intended, round explicitly, for example with DATEADD(MINUTE, DATEDIFF(MINUTE, 0, value), 0), so the loss is a visible decision in the query text instead of a side effect of the target's declared type.

A DATETIME2 value written into a SMALLDATETIME column

Noncompliant code example

CREATE TABLE dbo.Slot (Id INT NOT NULL, StartsAt SMALLDATETIME NOT NULL);

GO
CREATE PROCEDURE dbo.AddSlot (@id INT)
AS
BEGIN
    INSERT INTO dbo.Slot (Id, StartsAt) VALUES (@id, SYSDATETIME());
END;

SYSDATETIME() returns a DATETIME2 value with seconds; StartsAt is SMALLDATETIME, so the stored value is silently rounded to the nearest minute.

Compliant solution

CREATE TABLE dbo.Slot (Id INT NOT NULL, StartsAt DATETIME2(0) NOT NULL);

GO
CREATE PROCEDURE dbo.AddSlot (@id INT)
AS
BEGIN
    INSERT INTO dbo.Slot (Id, StartsAt) VALUES (@id, SYSDATETIME());
END;

StartsAt is now DATETIME2(0), which keeps the seconds, so nothing is rounded away.
